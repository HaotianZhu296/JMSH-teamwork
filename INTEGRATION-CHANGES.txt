1. UNIFIED DATA FORMAT (Part A → Part C/D)
------------------------------------------
Problem:
  Part A published MQTT telemetry as CSV lines using Electric Motor
  Temperature dataset fields (stator_winding, coolant, ambient, etc.).
  Parts C and D expected JSON with AI4I 2020 field names (airTemperature,
  processTemperature, rotationalSpeed, torque, toolWear).

Fix:
  Added TelemetryJson.java alongside the existing TelemetryCsv.java.
  The simulator now publishes JSON with the unified field mapping:

    Electric Motor field     →  Unified JSON field      →  Part C DTO field
    ─────────────────────────────────────────────────────────────────────────
    ambient (°C)             →  airTemperature           →  airTemperature
    stator_winding (°C)      →  processTemperature       →  processTemperature
    motor_speed (rpm)        →  rotationalSpeed           →  rotationalSpeed
    torque (Nm)              →  torque                    →  torque
    (not in dataset)         →  toolWear = 0.0            →  toolWear
    (preserved)              →  profileId, sampleIndex, coolantC, iD, iQ, uD, uQ

  SensorSimulatorTest updated to validate JSON output instead of CSV.

Files changed:
  - NEW  src/main/java/.../pipeline/TelemetryJson.java
  - MOD  src/main/java/.../pipeline/SensorSimulator.java (line 122)
  - MOD  src/test/java/.../pipeline/SensorSimulatorTest.java
  - NEW  src/test/java/.../pipeline/TelemetryJsonTest.java


2. PART C COMPILATION FIX (Lombok + JDK 25)
--------------------------------------------
Problem:
  Lombok 1.18.36 crashes on JDK 25 with TypeTag::UNKNOWN error.
  Also, annotation processor not configured in maven-compiler-plugin,
  so @RequiredArgsConstructor and @Builder were silently ignored.

Fix:
  - Added <annotationProcessorPaths> in detection-alert/pom.xml
  - Upgraded Lombok to 1.18.48 (supports JDK 25)

Files changed:
  - MOD  detection-alert/pom.xml
